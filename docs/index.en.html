Minecraft Server Management System

Run a server on your own PC,
then let it hold itself up.

A set of tools for a Windows machine at home. Starting a server is easy; keeping one running is not — something has to restart it when it dies, back the world up, and tell you which layer broke when a friend cannot get in. That is the part this handles.

Diagnostics

When it breaks, know which layer broke

01Local serviceis the server process aliveOK
02DNSdoes the domain point where it shouldOK
03Tunnelcan this machine reach the public addressFAIL
04Outside viewcan anyone else get inFAIL
05Web mapdoes the map site respondOK

Six layers, top to bottom, because a failure below is usually caused by one above. There is only one problem in the state shown here — the tunnel is down — and the outside-view check going red with it is just the consequence. Start at the topmost failure and you never spend time chasing the second symptom.

What it does

The six things it handles

01

Lets people in from outside

A home connection has no static IP and cannot open a port. A playit tunnel gets around that without touching the router; with a public IP you can forward ports directly instead. Friends on Bedrock — phones, tablets, consoles — join the same server through Geyser and Floodgate, with no Java account.

02

Gets itself back up

A watchdog checks every five minutes and restarts a server that died, and it can tell "you pressed stop" from "it fell over". Repeated failures stop the loop and leave a record, rather than restarting something broken forever.

03

Backs up without corrupting the world

Pause auto-save, flush the world to disk, copy, compress — then confirm auto-save actually came back on, and leave a warning file and a notification if it did not. A backup script that leaves saving switched off is the easiest disaster to cause and the hardest to notice.

04

Warns before it restarts

Scheduled restarts announce at five, three and one minutes, count down the last thirty seconds, and save before stopping. Nobody gets dropped mid-build.

05

Manageable while you are out

A Discord bot checks status, starts and stops the server and runs console commands, replying only to you. No remote desktop needed to reach the machine.

06

Installs in one program

The installer fetches Paper, downloads plugins, turns RCON on, writes the config, registers the scheduled tasks and adds the firewall rule. Every step can be unchecked.

Limits

What it deliberately does not do

This was written for one machine at home, not as a general server platform. Worth knowing before you start:

  • Windows onlyThe scripts use Task Scheduler, PowerShell and Windows Firewall. There is no Linux or macOS build.
  • One server at a timeNo multiple instances, no multiple users, no permission tiers.
  • The console is LAN-onlyIt can run any console command, so it is deliberately not exposed. Use the Discord bot to manage the server from outside.
  • The interface is in Traditional ChineseCode comments and commit history are in English, but the text users see has no English version.
